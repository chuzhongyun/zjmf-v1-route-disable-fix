# 魔方财务 /v1 接口"免费午餐"（0元购）漏洞修复

本项目是针对文章《[「26.08.17」藏在 /v1 接口里的"免费午餐"——魔方财务漏洞披露](https://blog.xn--s7qq40o.online/archives/1786958980336)》所述漏洞的修复补丁。

## 适用版本

- 适用于 `data/route/openapi.php` 中存在 `Route::group("v1", ...)` 路由定义的魔方财务版本。
- 若系统已移除 /v1 路由，或不确定是否存在该漏洞，请先确认路由定义后再决定是否安装。
- 本补丁基于魔方财务解码源码完成代码核对和设计。

## 修复的漏洞

| # | 漏洞 | 风险等级 | 摘要 |
| --- | --- | --- | --- |
| 1 | 0元购 | 严重 | 结算接口信任客户端传入的折扣参数，传 `0` 可将订单金额归零，账单直接置为已支付并开通服务 |
| 2 | 同类折扣参数信任（面板/升级入口） | 高 | 客户端面板结算与产品升级接口存在同类参数信任问题，可绕过 /v1 限制复用 |

## 此漏洞可能造成的后果

- 攻击者可通过结算接口构造折扣参数为 `0` 的请求实现 0 元购，服务直接开通
- 折扣参数可随查询串、表单或 JSON 请求体提交，WAF 等外层防护难以识别
- 同类问题可出现在面板结算、产品升级等入口，仅禁用单个接口无法根治

## 补丁原理

补丁在 ThinkPHP 启动、进入路由解析前检查请求：

- 拦截所有外部请求携带的折扣参数（查询串、表单、JSON 请求体均覆盖，含数组参数绕过）
- 命中即返回 HTTP 400，不再进入结算/升级逻辑
- 默认**不**禁用 /v1 接口，正常结算、查询、登录等对接调用完全不受影响
- 如需整体关闭 /v1 开放接口，将补丁内开关置为开启后生效（可选）

与 WAF 不同，本补丁运行在 PHP 应用进程内，检查的是框架实际解析到的请求数据，请求变形无法绕过。

## 注意事项

1. 本补丁默认仅拦截折扣参数，不影响任何正常对接调用（正常结算与升级请求不会携带该参数）。
2. 折扣参数仅在服务端内部向资源方下单时由系统计算生成，客户端与对接方不应提交该参数，拦截后不影响合法业务。
3. 如需整体禁用 /v1 开放接口（如不再对外提供该接口），打开补丁内的路径拦截开关即可，两种模式互不冲突。
4. 这是一项紧急缓解措施。永久修复仍应在结算与升级逻辑中对折扣类参数做服务端计算与范围校验。

## 安装方式

1. 将 `zjmf-v1_route_disable_fix.php` 放到魔方财务项目根目录。
2. 在 `public/index.php` 中加载补丁。补丁应放在 ThinkPHP 基础文件之后：

```
require CMF_ROOT . 'vendor/thinkphp/base.php';
require CMF_ROOT . 'zjmf-v1_route_disable_fix.php';   // <-- 添加此行
Container::get('app', [APP_PATH])->run()->send();
```

如果已经安装其他启动补丁，保持各自的 `require` 行即可。

## 卸载方式

从 `public/index.php` 中删除对应的 `require` 行，然后删除项目根目录下的 `zjmf-v1_route_disable_fix.php`。
